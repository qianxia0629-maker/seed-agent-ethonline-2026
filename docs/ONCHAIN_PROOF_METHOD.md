# Onchain Proof Method

Seed Agent uses a deterministic activity score to summarize evidence returned by The Graph. It is designed for talent discovery, not financial decisions.

## Live data coverage

- Provider: The Graph decentralized network gateway.
- Indexed network: Ethereum mainnet.
- Public source: `Uniswap V3 Mainnet` (`9fWsevEC9Yz4WdW9QyUvu2JXsxyXAxc1X4HaEkmyyc75`).
- Wallet evidence: Uniswap V3 liquidity mints, burns, fee collections, and owned liquidity positions.
- Recent window: 90 days.
- Activity count: unique transaction hashes, so several events in one transaction count once.
- Freshness proof: every successful response includes the Subgraph's indexed block.

The current proof does not claim to cover every Ethereum transaction, every chain, wallet balances, net worth, creditworthiness, identity uniqueness, or professional ability. A network or protocol is marked verified only when the queried data contains wallet-specific evidence.

## Score

The score is calculated in code and is not generated by an AI model.

| Component | Maximum | Rule |
| --- | ---: | --- |
| Activity history | 30 | 8 points when evidence exists, plus 7 for each complete year, capped at 30 |
| Recent activity | 40 | 4 points per unique transaction in the last 90 days, capped at 40 |
| Active positions | 20 | 10 points per owned position with non-zero liquidity, capped at 20 |
| Protocol evidence | 10 | 10 points when Uniswap V3 wallet evidence exists |

Maximum total: 100.

The interface calls this an **Onchain Activity Score**. It must not be described as a credit score, reputation guarantee, proof of skill, or measure of a person's value.

## Empty and capped results

- A successful live query with no wallet evidence returns a score of `0`, empty verified-network and verified-protocol lists, and a visible no-evidence message.
- There is no mocked or estimated fallback.
- Each recent event type is limited to 100 records per query. If a limit is reached, the response marks the result as capped and the interface discloses that limit.
- Provider, authorization, and timeout failures remain visible errors rather than being converted into a score.
